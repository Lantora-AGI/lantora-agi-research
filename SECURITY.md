# Security Policy

## Reporting a vulnerability

Do not open a public Issue for vulnerabilities, exposed credentials, private data, sandbox escapes, or findings that could materially enable dangerous capabilities.

Until GitHub private vulnerability reporting is enabled, contact an organization owner privately through their verified GitHub profile. Do not include exploit details in a public Discussion. The project will add a dedicated security contact before accepting executable systems from outside contributors.

Include, where safe:

- affected component and version;
- impact and required preconditions;
- minimal reproduction steps;
- suggested mitigation;
- whether the issue is already public.

Do not access data that does not belong to you, degrade services, or expand testing beyond the minimum needed to demonstrate the issue.
